02 · HIGH SEVERITY

已确认的高危问题

以下每项都经独立的怀疑者代理阅读实际代码后确认（30/32 核实通过，0 项被驳回）。

1. YAML 往返静默腐蚀 "null" / "~" 字符串 —— 数据损坏

HIGH已核实
TestFramework.SequenceYaml/TestSequenceYamlService.cs:11

实测（YamlDotNet 16.3.0）：Variables/Settings/Parameters 中的字符串值 "null"、"~"、"Null" 保存时被序列化为不加引号的标量，重新加载后变成 null。这与项目拒绝注释/锚点的全部理由（往返保真）直接冲突，用户数据在无提示下被篡改。

修复建议在 SerializerBuilder 上挂自定义 IEventEmitter，对 null 类词强制单引号标量；补 "null"/"~" 字符串往返单元测试。

2. release 打包预计必失败（NU5039）

HIGH已核实
Directory.Build.props:9-11

Condition="'$(IsPackable)' == 'true'" 因 MSBuild 求值顺序恒为 false（props 在 csproj 正文前求值），README.md 永远不会进包；而无条件设置的 PackageReadmeFile 又要求它必须在包内。release.yml 的 dotnet pack 很可能从未成功过。

修复建议移到 Directory.Build.targets 或去掉 Condition；在 PR CI 加一次 dotnet pack 冒烟验证 release 路径。

3. 深度嵌套 YAML 栈溢出 → 进程级持久化启动崩溃（已实测复现）

HIGH已核实
TestFramework.SequenceYaml/TestSequenceYamlService.cs:33 · TestFramework.App/Services/SequenceDocumentStore.cs:76

YamlDotNet 解析深嵌套文档直接 StackOverflow 杀进程，catch (Exception) 拦不住；启动时加载序列目录即触发——一个损坏文件让应用再也起不来。

修复建议解析前限制文档嵌套深度（预扫描缩进层级），坏文件隔离而非整进程崩溃。

4. UI 层三项高危：删除无确认 · async void 无兜底 · 1847 行上帝类

HIGH已核实
TestFramework.App/Views/SequenceEditorView.axaml.cs

删除磁盘序列文件无任何确认（:864-892），不进回收站，与关闭流程的三选确认形成反差。 部分 async void 处理器无兜底 catch（:1312-1346 及 StepEditorWindow 构造），第三方插件代码抛异常可直接终止进程。 无 MVVM：ViewModels/Controls/Models 三个目录为空，全部状态与逻辑集中在 1847 行代码隐藏中，测试被迫用反射调私有方法。

修复建议删除加确认对话框；async void 统一兜底；把 UI 无关逻辑（克隆、变量改名、判定写入）下沉为可独立测试的文档服务类。

5. 插件体系：机制先进、收尾粗糙

HIGH已核实（核后降为 MEDIUM）
TestFramework.Core/Plugins/PluginLoader.cs:29,95-114 · PluginAssemblyCatalog.cs:36-54

逐类型故障隔离弱于资源插件：一个坏类型拖垮整个程序集，与 ResourcePluginLoader 的逐类型捕获不一致。 目录扫描噪音：原生/依赖 DLL 都被当插件加载，失败报告误导用户。 卸载名存实亡：插件注册后引用链永久根化，DLL 更新必须重启进程，且文档完全未声明。

修复建议统一两个加载器隔离粒度（ReflectionTypeLoadException 抢救 ex.Types）；加载前轻量过滤候选 DLL；文档补齐"不可卸载/更新需重启/共享程序集清单"。

05 · BLIND SPOTS

完整性检查发现的项目盲区

最后的完整性批评代理通览仓库后，指出八维度评估之外真实存在但被遗漏的项目问题。

数据路径全部硬编码在程序目录下

插件目录、config/sequence、results 全部在 AppContext.BaseDirectory 下（SequenceEditorView.axaml.cs:228,398-402），无 %AppData% 回退——安装到 Program Files 等只读位置时保存与写结果直接失败；主题切换不持久化；results 只写不读、无限堆积。

无撤销体系

删除步骤、拖拽移动/复制、参数编辑全部不可撤销；模型对象被事件处理器原地修改，误操作无回退路径；全库无 AutomationProperties，键盘可达性缺失。

日志 O(n²) 且无日志框架

LogBox.Text += 逐行拼接（:752），每步一次 Dispatcher.Post 无节流，大序列下 UI 线程被事件洪峰占满；长序列运行时内存无界增长。

拖拽链路缺陷

TestStepDefinition.Clone 对非 POCO 参数抛 InvalidOperationException（:73）——插件放入不可克隆参数时 Ctrl+拖拽复制即崩；约 200 行近期高频改动的拖拽逻辑测试最薄。

示例文件无自动化校验

Samples/sample-sequence.yaml 是用户最主要的模仿对象，但全库无测试或 CI 步骤引用它，与校验器规则漂移不会被发现。强制软件渲染（Program.cs:17-21）无注释说明动机。
