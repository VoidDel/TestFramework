# TestFramework 功能完整性评估（2026-10-10）

基线：`main @ 13d3128`（v0.5.2）。本机实测 `dotnet build` 0 警告，`dotnet test TestFramework.sln -c Release` 386 个用例全部通过。仓库 19 170 行 C#、8 个项目、5 个 release tag。下游宿主 `BMS-TEST` 锁定 v0.5.1，其 `Plugins/` 目录目前只有内置的 `BasicSteps`。

本文只回答一个问题：**作为 BMS 产线测试上位机的框架核心，它承诺的功能有哪些已经做完、哪些有缺口、哪些还没开始。** 代码质量与架构合理性见前几份评估，不再重复。

## 总体结论

框架核心的功能面**基本完整**：序列描述、校验、执行、判定、资源、工位编排、结果追溯这条主链每一环都有实现、有测试、有文档，而且 README 承诺的行为与代码一致（逐条抽查未发现文档超前于实现的情况）。

缺口集中在三类：

1. **量纲覆盖窄**：单位表只有 18 项，BMS 日常用的 `°C`、`Ah`/`mAh`、`W`/`Wh`、`min`/`h` 都不认识，且表是 `internal static`，宿主无法扩充。这是唯一一处"按文档写序列会在运行时判 `Inconclusive`"的功能缺口。
2. **序列级安全收尾缺失**：只有测试项级 `cleanup`，没有"无论在哪一项停下都要执行"的序列级 teardown。对充放电测试，"把 DUT 置于安全状态"目前只能靠每个测试项各写一份。
3. **域层为零**：框架把仪器、传输、服务三类资源契约都定义好了，但仓库内没有任何参考实现（仅测试里的假驱动），宿主也还没有一个 BMS 步骤插件。契约是否好用，尚未被真实驱动验证过。

运行时调试能力（暂停、单步、只跑选中项）与时序数据记录是两块**未实现**的功能，属于后续版本，不影响当前承诺。

## 逐项说明

### 单位表（最该先补的一项）

`UnitConverter` 的规则本身是对的：单位不认识或量纲不一致就判 `Inconclusive`，绝不裸比。问题是表太小。BMS 序列里"电芯温度 `25.3 °C`、限值 `unit: C`"会因 `°C` 不在表里直接 `Inconclusive`；容量 `Ah`、功率 `W`、能量 `Wh` 根本没有量纲。表是 `internal static`，宿主和插件都无法登记新单位，于是插件作者只能把测量值预先换算成框架认识的单位再返回，这正好违背"仪器比序列更清楚自己返回了什么"的设计意图。

建议：补齐温度（`°C`、`degC`、`K`）、电荷（`Ah`/`mAh`/`C`——注意与温度的 `C` 冲突，需要决定裸 `C` 归谁）、功率、能量、时间（`min`/`h`）、电容；并给宿主一个注册入口。工作量小，收益直接。

### 序列级 teardown

`onError: stop` 停在第 3 项时，只跑第 3 项自己的 `cleanup`；第 10 项 `cleanup` 里的"断开充电回路"不会执行。取消时同理。现在的替代办法是每个可能停下的测试项都写一份断电清理，或者宿主在结果返回后自己操作硬件——后者绕开了序列，结果里没有记录。

一个 `TestSequence.Teardown` 段（无论如何结束都执行、与取消清理共用 30 s 宽限、被隔离时跳过）与现有执行规则是相容的，`cleanup` 的全部语义可以直接复用。

### 表达式

BMS 的故障字、状态字按位解释是日常操作，`${faultWord} & 0x0004 != 0` 现在写不出来，只能让插件把每一位拆成独立输出。字典输出（信号表）在表达式里被转成值列表（`SequenceExpression.cs:141`），`${signals}['SOC']` 不可用，要读某个信号就得让插件单独输出它。两者都是解析器层面的小改动。

### 资源健康与重连

工位级资源跨运行保持打开，这是对的。但驱动契约只有 `CreateAsync`，没有"你还活着吗"：USB-CAN 被拔掉后，下一次运行会先拿着死句柄跑到第一个 `Error`，然后才在再下一次运行重建。一个可选的 `IResourceHealthCheck`（默认实现返回健康）让 `TestRunSession` 在开始运行前探测一次，就能把"跑坏一台 DUT 再重连"变成"开始前重连"。

### 观察者与日志

事件集合够宿主画进度树；缺的是日志的结构。`Action<string>` 把级别、来源、时间都压进了文本，宿主只能原样追加。对产线排障，至少需要级别；接 `Microsoft.Extensions.Logging` 不改契约也能做（`Log` 保留，新增可选的 `ILogger`）。

### 操作员交互

`OperatorPrompt` 只有选项。步骤需要操作员录入一个值（读条码、输入目测的指示灯状态）时没有办法。加一个 `PromptInputAsync` 带默认实现即可留在契约 1.x。

### 本地化

`ValidationIssue` 只有 `Path` + `Message`，`TestStepResult.ErrorMessage` 是运行器拼的英文句子。宿主无法在不解析字符串的前提下翻译，而 `BMS-TEST` 的操作员界面是中文。`TestRunRefusal` 已经证明"枚举原因 + 宿主措辞"是可行的模式，校验器的三十余种问题和运行器的十余种错误可以同样处理。

### 域层尚未开始

这不是框架的缺陷，但决定了"功能完整"的实际含义。资源契约（仪器、传输、服务）与 `exclusive`、通道视图等用法目前只在单元测试的假驱动上验证过。第一个真实的 CAN 传输 + UDS 服务 + 电源驱动写出来之前，契约里"好用不好用"的问题（`CreateAsync` 拿到的 `Settings` 够不够、传输与服务怎么分层、`Dispose` 顺序对不对）都还没被问过。建议在框架仓库内放一个最小的参考资源插件链（可以是回环/模拟的），和 `BasicSteps` 一样按插件方式交付。

## 测试覆盖

386 个用例的分布与功能矩阵一致：校验器 27、运行器 25、流程控制 25、测量判定 20、多判定点 18、工位资源 13、YAML 11、表达式 10、产线资源 9、会话 8、跨进程锁 6。没有哪个"完整"项是只靠文档撑着的。

两处覆盖薄弱：单位换算没有独立测试文件（散在判定用例里），这与它是最大缺口相呼应；资源插件加载只有 1 个用例。

## 建议顺序

1. **单位表扩充 + 可注册**：小改动，解除 BMS 序列的直接障碍。
2. **序列级 teardown**：安全相关，语义可复用 `cleanup`。
3. **表达式位运算与字典取值**：小改动，解除故障字与信号表的间接写法。
4. **参考资源插件链**：用真实形状验证资源契约，先于任何 BMS 域插件。
5. **校验/运行错误码**：让宿主能翻译。
6. **资源健康检查**、**操作员输入**、**结构化日志**：各自一个带默认实现的新成员，可在契约 1.x 内完成。
7. **工作进程**：维持设计文档的判断——先回答 DUT 安全状态，再动手。
8. **运行时控制与时序数据**：下一版本的功能，不阻塞当前产线落地。

## 本轮已落实

建议顺序的前三项已完成，`dotnet test` 从 386 增至 447 个用例全部通过，0 警告：

- **单位表扩充 + 可注册**：新增 `TestFramework.Abstractions/Models/MeasurementUnits.cs`，Core 的 `UnitConverter` 改为委托给它。表从 18 项扩到 50 项（温度含 `°C`/`℃`/`degC`/`K`，新增电量、功率、能量、电容、`mOhm`、`min`/`h` 等），支持带偏移的换算（K ↔ °C）。符号先精确匹配、再唯一时不区分大小写——`mOhm` 与 `MOhm` 因此得以共存，原先 `OrdinalIgnoreCase` 的表根本放不下两者。`Register` 对宿主与驱动开放，同定义重复登记为空操作、改定义抛异常。校验器新增两条：未知单位警告，`sourceUnit` 与 `unit` 量纲不一致报错。`MeasurementUnitsTests.cs` 24 个用例，含 `"25.3 °C"` 端到端判定。
- **序列级 `cleanup`**：`TestSequence.CleanupSteps`，YAML 顶层 `cleanup:`（为空时不写，旧文件逐字节不变）。运行器在全部测试项之后执行——正常结束、`Stop` 中止、流程定义出错、取消（与测试项清理共用同一个 30 秒宽限窗口，而不是各占一个）——以保留 id `$cleanup` 作为一个测试项报给观察者并记入 `TestSequenceRunResult.Cleanup`；步骤被隔离时跳过并逐步记 `Skipped` 原因；其 `Fail`/`Error` 决定序列结论。校验器在测试项留下的变量作用域里检查它，并拒绝占用保留 id 的测试项。`SequenceCleanupTests.cs` 10 个用例覆盖以上每条，`Samples/flow-sequence.yaml` 加了示例。BMS-TEST 的进度树按 `FindOrAdd` 处理未知测试项，无需改动即可显示该节点。
- **表达式位运算与字典取值**：新增 `& | ^ ~ << >>`、十六进制字面量 `0x04`；位运算只接受整数且比比较运算绑得更紧（Python 优先级），`${faults} & 0x04 != 0` 按直觉成立。字典不再在进入表达式时退化为值列表，`${signals}['SOC']` 按字典自身的键比较规则取值，聚合函数对字典取其值。`SequenceExpressionTests` 新增 27 个用例。

三项都是 Abstractions 的增量公开 API，插件契约仍为 1.1；按 semver 应发 **0.6.0**。未动的：参考资源插件链、错误码、健康检查、操作员输入、结构化日志、工作进程、运行时控制与时序数据。
